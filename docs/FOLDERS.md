# 资料与文件夹：谁、在什么场景、要完成什么

> 写给实现者（含未来的自己）。动代码前先看这一页。
> 现状：文件夹区（新建 / 拖拽移动 / 批量移动 / 删空文件夹 / 面包屑）已落地并在生产实测过；
> 下面第四节之后是**按场景推演出来的缺口**，按价值排序，逐条决定要不要做。

---

## 一、四个角色，四种真实动作

| 角色 | 在什么场景下 | 要完成什么 | 怎样才算完成 |
|---|---|---|---|
| **管理员**（人） | 白天收了一批资料；手机上批申请；隔几天回来找一份旧方案 | 把资料归位、定谁能看、把地址发出去 | 不用翻磁盘目录就能完成；手机上也能批、也能挪 |
| **同事**（L1/L2/L3） | 客户催报价，想知道"有没有 XX 方案"；拿到原件直接转发 | 找到 + 下载 / 让 AI 读给他 | 1 分钟内自己找到，不用问管理员"在哪个文件夹" |
| **外部 AI 客户端** | 同事在 ChatGPT 连接器里问问题 | 按地址检索、读正文、拿限时链接 | 命中率够、能按项目/文件夹范围检索、答案带出处 |
| **维护者（agent）** | 批量整理、巡检、审计 | 批量动权限/归位、发现异常 | 有 CLI/接口可用，动作都留痕 |

**推论**：管理员要的是「整理效率」，同事要的是「找得到」，AI 要的是「范围与出处」，agent 要的是「可批量、可审计」。
四者里最容易做偏的是同事那一侧 —— 现在同事看到的还是**一长条平铺列表**，没有项目/文件夹的概念。

---

## 二、首次使用（空库 → 能发出去）

真实顺序：**建文件夹 → 传资料 → 定等级 → 发地址**。

1. 建文件夹：按什么分？现实里是「项目/客户」或「年份/阶段」。一次会上传整个文件夹，层级自动建出来。
2. 传资料：拖整个文件夹最省事（已有，层级保留）；单个文件补传。
3. 定等级：**批量**定（已有），不要一篇篇点。新文件默认继承文件夹等级（见第九节建议 2）。
4. 发地址：邀请码 / 管理页直发 / 命令行（已有）。

**完成标准**：同事拿到地址后，**没有问任何问题**就找到了第一份资料并下载下来。
→ 所以同事侧必须能按文件夹/项目浏览，而不是靠猜关键词。

## 三、再次使用（日常，最高频）

- 往**已有文件夹**里加一批新资料 → 需要：上传时能直接选目标文件夹（已有：上传区默认跟着当前位置）
- 找一份旧资料 → 需要：搜索（标题/编号/路径，已有）、面包屑回到上层（已有）、**最近操作**（缺）
- 调权限：一篇 / 一批（已有）/ **一整个文件夹**（缺，见建议 2）
- 挪位置：拖拽（已有）/ 下拉+按钮（已有，手机用）/ 多选批量移动（已有）
- 同事问"为什么我看不到 X" → 需要：按人看用量与拒绝记录（已有 `kb usage`、管理页用量看板）

## 四、数据积累（100 篇 → 1000+ 篇）

会出现的症状与对策：

| 症状 | 对策 | 现状 |
|---|---|---|
| 文件夹 2–3 层、几十个，列表太长 | 文件夹列表只显示当前层的子文件夹 + 超过 N 个加过滤框 | 部分（只显示当前层 ✓，过滤框缺） |
| 记不清哪篇公开过 | 状态筛选 + 等级筛选（已有）+ 按时间排序（缺） | 部分 |
| 找不到"上个月传的那份" | 搜索跨文件夹（已有）+ 最近操作（缺）+ 按上传时间排序（缺） | 部分 |
| 同事侧平铺太长 | 同事侧按文件夹分组 + 打包下载整个文件夹（缺） | 缺 |
| 不知道谁看过 | 审计 + 用量看板（已有） | 有 |

**判断标准**：1000 篇时，管理员用 3 步内定位一篇；同事用 2 步内定位一篇。

## 五、状态变化（资料是会动的）

| 变化 | 现在的行为 | 风险 / 待定 |
|---|---|---|
| 同名同内容重传 | 不新建条目（sha256 判重）✓ | — |
| 同名不同内容 | 退回待批，等级保留旧值 ✓ | — |
| **移动文件** | 台账 path 跟着改，doc_id 换（id = sha256(路径)），状态/等级/审批记录保留 ✓ | 已发出的**限时下载链接**会失效 —— 但签名只有 15 分钟，可接受；**MCP 地址不受影响** |
| **改文件名** | 现在只能改台账显示标题（缺：连标题都还不能改） | 改磁盘名会让 doc_id 变、判重记录错位 → 建议只改显示标题 |
| **删除** | 只能"移除条目（不删文件）" | 建议加"回收站"（移进 `.回收站/`，30 天可恢复），不做真删 |
| 文件夹清空 | 可删空文件夹 ✓（非空、或台账里还有引用 → 拒） | — |
| 同事过期/离职 | 地址停用、立刻失效 ✓ | — |

## 九、建议的下一步（按价值排序，等你拍板）

1. **同事侧按文件夹分组 + 按文件夹打包下载**（同事"找得到"的最大短板；AI 侧同步支持 `folder` 参数）
2. **文件夹默认等级**：新建文件夹时设一个默认等级，新进来的文件继承；台账仍逐篇记录（保留逐篇兜底与"内容变更退回待批"）
3. **整理三件套**：多选移动（已有）、**回收站**（替代真删）、**改显示标题**（不动磁盘名）
4. **大库导航**：跨文件夹搜索（已有）、按上传时间/等级排序、**最近操作**面板（谁动了什么，可一键回看）
5. **移动端**：文件夹区窄屏排版、按钮加大、长名字截断 + 悬停看全
6. **AI 侧**：`kb_list` 输出带文件夹路径；`kb_search` 支持 `folder` 限定；答案里带出处（已有 doc_id/路径）

## 九·五、文件夹的语义：**一个任务需求**（用户 2026-09-24 定，最重要的一条）

**文件夹 = 一个任务/需求，不是一类文件。** 同一个需求下的东西，不管它是什么类型
（需求说明、报价、资质、图纸、会议记录…），都放进**同一个文件夹**；反过来，
两份都是「报价单」但服务不同任务，就该在**不同**文件夹里。

推论（改归类逻辑时必遵）：

1. 不要按文件类型建文件夹（`商务/技术/资质/公示/交付` 这类目录名是错的）；
2. 归类建议要找的是**共同的任务标识**（项目名、任务代号/编号），不是「这份文件是什么类型」；
3. **找不到共同标识就不要建议** —— 宁可不提，也不硬塞（免得把人带偏）；
4. 文件夹名由人定，AI 只提议（`kb suggest` 出方案、`kb apply` 才动文件）。

## 十一、实施清单（按上面五条展开）

1. 文件夹默认等级：台账里存 `folders.<路径>.level`，子文件夹未设则向上继承；上传区默认跟随、扫描/新增文件按文件夹等级落档；管理页文件夹行可改
2. 回收站：整棵文件夹或单篇进 `.回收站/<时间>-<名字>/`；台账条目记 `trashed` + `prev_status`，可恢复、可彻底删；`kb trash` 列/恢复/清理；30 天自动清理
3. 同事侧：资料页按文件夹分组（可折叠）+ 每个文件夹一个「打包下载」（限他等级内）
4. AI 侧：`kb_list`/`kb_search` 带文件夹路径与 `folder` 限定参数
5. 改名：行内改显示标题（`kb title`）
6. 大库导航：文件夹过滤框、按上传时间/等级排序、最近操作面板
7. 移动端：文件夹区窄屏排版、按钮加大
8. 测试：⑬ 文件夹（新建/移动/删除/回收站/默认等级/边界）与同事侧分组打包

## 十三、落地情况（2026-09-24 已实现并实测）

| 能力 | 怎么用 | 实现位置 |
|---|---|---|
| 新建文件夹 | 管理页「文件夹」区 → 填名字 → 新建（自动进去） | `POST /admin/mkdir` · `FOLD.mkdir` |
| 拖文件到文件夹 | 资料行拖到文件夹行上放下（桌面宽屏）；手机/触屏用行内「文件夹」下拉 + 「移动」 | `POST /admin/move` · `FOLD.move_file` |
| 批量移动 | 勾选多篇 → 「移到 <文件夹>」 | `POST /admin/move` · `_move_many` |
| 删文件夹 | 文件夹行「删除（进回收站）」→ 整棵进 `.回收站/`，里面的资料一起标记 | `POST /admin/rmdir` · `FOLD.to_trash` |
| 文件夹默认等级 | 文件夹行选等级 → 「存默认等级」；新进来的文件继承（显式选的等级优先） | `POST /admin/flevel` · `KB.set_folder_level` |
| 回收站 | 管理页「回收站」区：放回原位 / 彻底删 / 清理 30 天前的 | `POST /admin/trash` · `FOLD.list_trash/restore_trash/purge_trash` |
| 单篇进回收站 | 资料行「进回收站」，或批量勾选后「放进回收站」 | `POST /admin/bulk` · `one=<id>@trash` |
| 改显示标题 | 资料行标题框直接改 → 「改标题」（只改台账标题，磁盘名不动） | `POST /admin/bulk` · `one=<id>@title` |
| 同事按文件夹看 | 同事资料页按文件夹分组（可折叠），每组带「打包下载这个文件夹」 | `GET /files` · `POST /zip`（`folder=`，根目录用 `.`） |
| AI 按文件夹查 | `kb_list(folder="技术")`、`kb_search(keyword, folder="技术")`，输出带 `folder` 字段 | `core/kb.py` |
| AI 归位建议 | `bash lighthouse.sh kb suggest <窗口>` 出建议（按**任务需求**聚类：已有文件夹名命中 → 最强；否则找若干篇共享的项目名/编号）；`kb apply <窗口> <方案.json>`（先 `--dry-run`）才执行。**MCP 侧仍零写** | `core/kb_cli.py` |
| CLI 同款 | `kb mkdir / mv / title / flevel / trash / suggest / apply` | `core/kb_cli.py` |

**顺序规则（等级）**：上传时显式选的等级 > 所在文件夹（含父文件夹）的默认等级 > 窗口默认等级。
只影响**新进来**的文件；已入库的等级要改走逐篇「保存等级」或 `kb approve/set-level`。

**安全边界（照旧）**：`clean_rel()` 对 `../`、`.`、绝对路径、`~`、盘符、隐藏名、超 6 层、怪字符**一律拒绝**（不做"悄悄改写"，避免"删 /etc/x"变成删库里的 `etc/x`）；落盘前再 `resolve()` 校验仍在资料库内。MCP 侧仍然没有任何写能力。
