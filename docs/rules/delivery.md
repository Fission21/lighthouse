# 功能设计与交付流程

> 本文件是 [`AGENTS.md`](../../AGENTS.md) 的交付专项：需求怎么想、改完怎么验、交付怎么交代。
> 授权与数据保护边界以根 `AGENTS.md` 为准；页面视觉标准见 [`docs/DESIGN.md`](../DESIGN.md)。

按任务的影响和不确定性灵活执行，不逐项机械展开，也不默认扩大范围。

## 一、拿到需求先别写代码

1. **场景先行**：谁、在什么场景、要完成什么、怎样才算完成。推演首次使用、再次使用、数据积累、状态变化和后续流转。
   灯塔的场景里永远有三个角色：**窗口所有者**（用户）、**外部 AI**（网页 AI / 远程 MCP 客户端）、**同事**（受控资料库）。改之前先说清这次影响谁。
2. **复用核对**：先看现有能力再决定实现 —— `core/*.py` 的闸门与工具面、`lighthouse.sh` 子命令、门户组件（`_page` / `.card` / `.bar` / `_q` / `_pager` / `_copybtn`）、台账层（`kb.scan_library` / `set_status` / `save_catalog`）。
   不因为"看起来像"就合并两件事，也不为一次修复造新抽象；确需新增时说明现有能力为什么不够。
3. **先自己想，再查证**：涉及 MCP 协议行为、cloudflared 隧道、scrypt/HMAC、文件系统语义这类关键事实，查官方文档或实测，不凭印象；别人的方案不直接照搬。
4. **PLAN 口径**：带着推荐方案、理由和关键取舍与用户讨论；已明确的不重复确认，常规实现自主推进。

## 二、按改动类型选最小验证（别全跑，也别不跑）

| 改动 | 最小验证 |
|---|---|
| 文档 / 规则 / 文案 | `python3 tests/check_docs.py`（链接、ADR 编号、套件名、称呼、编码）+ `git diff --check` |
| `core/*.py`（闸门、脱敏、写、提权） | `bash tests/run_all_tests.sh` 全绿；安全相关改动必须补断言 |
| `core/kb_*.py`、门户页面、`core/theme.py` | 全套测试 + 真实浏览器走一遍受影响页面（桌面与约 390px） |
| `lighthouse.sh` 子命令 | 冒烟套件 + 受影响子命令实跑（含失败路径） |
| `windows.json` / `config.json` 示例 | 注册表校验 + 起一次窗口确认范围生效 |
| `pyproject.toml` / 依赖 | ruff + 全套测试 |

## 三、交付前的两类复查

1. **功能与交互**：从用户入口走通受影响流程 —— 开窗 → 连接 → 调用 → 门户页面（点击、筛选、分页、展开、下载、登录、退出、刷新），核对结果、状态与后续去向。
   必须覆盖：**拒绝路径**（该挡的挡住）、**数据规模**（空 / 一篇 / 多页）、**异常与恢复**（失败后能不能重试）。只看得见页面或接口 200 不算通过。
2. **视觉与排版**：门户页面在真实浏览器里核对层级、字号、间距、对齐、换行与截断、滚动与溢出、操作区与提示位置；桌面与约 390px 都要看；结合长文本、空值、多数据量检查布局稳定性。

只改文档时这两类不适用，但"链接打得开、命令跑得通、示例能照抄"仍要核对。复查发现的问题在本次目标范围内直接修掉，交付时说明修了什么。

## 四、交付怎么交代

- 说清：改了什么、关键文件、实际跑了什么、结果如何、**没验什么**。
- 证据分层：源码写了 / 本机跑过 / 真实浏览器 / 真机 / 线上，分别表述，不混着说。
- 测试没跑全就直说，不写"应该没问题"；不把定向通过说成全套通过。
- 遇到既有失败：**改动前先跑一遍基线**，确认不是本次引入，再继续；既不背锅，也不掩盖。

## 五、边界与授权

- 线上与用户数据：默认只读。改隧道、动 `~/.lighthouse/state`、删备份、清审计，要用户明确授权。
- 破坏性操作（`reset --hard`、强推、删窗口、删资料）必须有具体范围的授权。
- 令牌、管理令、邀请码、密码哈希、会话 cookie 不进仓库、日志、回执。
- 多 Agent：先划各自文件范围，同一文件不并行写；子 Agent 的"已完成"要自己复验，不算证据。
- 编码：UTF-8 无 BOM + LF；改中文文件优先用补丁，不整篇重写。

## 六、文档制度

- **长期决策**写 [`decisions/adr/`](../../decisions/adr/)（模板 `decisions/_template.md`），并同步 [`decisions/INDEX.md`](../../decisions/INDEX.md)；已采纳的 ADR 不改结论，取代就写新的并标注关系。
- **小坑与临时 workaround** 记 [`docs/ISSUES.md`](../ISSUES.md)：一条一个问题，证据必须能复现。
- **规范只写一处**：入口文件（本目录、根 `AGENTS.md`、`CONTRIBUTING.md`）只维护"引用 + 适用范围"，数值和规则留在规范正文，避免两处各写一套。
- 文档与实现不一致时，分清是**文档过时**还是**实现不满足约束**；不要用改文档掩盖实现问题，也别因为实现有问题就取消约束。
- 文档一致性由 `tests/check_docs.py` 兜底（链接、ADR 编号与索引、套件名、对外称呼、编码），它是套件之一，跟着 `run_all_tests.sh` 一起跑。
