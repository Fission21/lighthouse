# 0007 - 设计令牌单一来源与默认主题

- **状态**：已采纳
- **日期**：2026-09-24（记录既有决策；该行为自 0.6.0 起生效）
- **决策人**：项目所有者 + AI
- **标签**：#design-system
- **关键词**：`theme.py`, `设计令牌`, `teal`, `一个区块一个主按钮`, `完整链接`

## 一、背景

门户页面（申请页、查进度、管理页、资料页、下载页）会持续增加。颜色、间距、圆角、字号如果各页自己写，改一次配色就得翻遍所有页面，新人加页面也容易跑偏。

## 二、考虑的方案

| 方案 | 优点 | 代价 |
|---|---|---|
| A 每页自己写样式 | 局部灵活 | 改配色要全站翻一遍；风格漂移 |
| B 令牌集中在 `core/theme.py`，页面只引用变量 | 改一处全站变；可换主题 | 加新颜色要先改令牌 |

## 三、决策

选 **B**：

- 所有颜色 / 间距 / 圆角 / 字号 / 阴影定义在 [`core/theme.py`](../../../core/theme.py) 的 `THEMES`；页面里**不写死十六进制**（有断言盯着）。
- 内置三套主题：`teal`（松石绿，**默认**，用户选定）、`indigo`、`paper`，`kb theme <窗口> <名字>` 切换。
- 组件规范（`.card` / `.bar` / `.chip` / `.empty` / `_q()` / `_pager()` / `_copybtn()`）与「**一个区块只留一个主按钮**」「给用户看或复制的链接必须是完整地址」写进 [`docs/DESIGN.md`](../../../docs/DESIGN.md)。
- 可访问性底线：焦点可见、按钮高度 ≥ 32px、**不靠颜色单独传信息**（状态胶囊永远带文字）。
- 纯视觉改造**不得**改变业务、字段与信息架构。

## 四、后果与风险

- 正面：换主题全站一起变；新人照模板加页面不会跑偏；颜色与语义解耦（`--brand` / `--danger` 而不是"那个蓝色"）。
- 代价：加颜色要走 `theme.py`（略慢一步）；三套主题都要保持对比度达标。
- 持续跟踪：新页面是否仍然零硬编码颜色（靠断言兜）；移动端（约 390px）布局与长表格横向滚动。
