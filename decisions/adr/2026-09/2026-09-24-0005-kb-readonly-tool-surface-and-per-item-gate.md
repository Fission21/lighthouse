# 0005 - 资料库只读工具面与篇级闸门

- **状态**：已采纳
- **日期**：2026-09-24（记录既有决策；该行为自 0.6.0 起生效）
- **决策人**：项目所有者 + AI
- **标签**：#security #authorization #gate
- **关键词**：`kb_*`, `只读工具面`, `篇级闸门`, `一人一条地址`, `签名链接`, `台账`

## 一、背景

受控资料库（kb 模式）面向的是**外部同事**，不是 AI：同一份资料要按人、按等级、按篇控制可见性，还要能下载原件。普通窗口的工具面（含写工具，靠拒绝挡）不足以表达"这一篇给不给他看"。

## 二、考虑的方案

| 方案 | 优点 | 代价 |
|---|---|---|
| A 复用窗口工具面，靠闸门拒 | 一套代码 | 写工具注册着就有风险；粒度只能到路径 |
| B 单独的 kb 只读工具面 + 篇级台账 | 工具面即边界；粒度到篇 | 两套工具面要各自维护 |

## 三、决策

选 **B**，并把闸门顺序固定下来：

- **只注册只读工具**：kb 模式下路径型工具（`list_files` / `read_file` / `search`）与写工具**根本不注册** —— 外部 AI 连工具名都看不到，比"注册了再拒绝"少一个洞。
- **篇级闸门顺序固定**：未批准 → 等级不符 → include/exclude/拉黑 → 越界 → 原文件哈希变了 → 文本缺失；任何一步不过就拒。**审批与等级都覆盖不了默认拉黑**；等级**不做继承**（要包含就显式列）。
- **只有维护者侧能改"公开/授权"**：CLI 与管理页可以，MCP 工具一个都没有；台账或同事记录坏掉 → 一律拒。
- **一人一条地址**：令牌是 URL 的一部分（网页版 AI 只能填 URL，没有自定义 header 输入框）；改权限不换地址，`rotate` 才换；管理令 `adm_` 前缀与同事地址互不通用。
- **下载与在线阅读共用同一道闸门**：门户下载页、单篇下载、打包、`kb_link` 全都先过 `kb.resolve_doc`；签名链接必须**验签**（绑定篇号 + 人 + 到期），且签名只绑一篇 —— 不能拿签名链接去列清单或打包。
- **管理页的写操作走台账层**（`kb.scan_library` / `kb.set_status` / `kb.save_catalog`），不在网页层直接改 JSON；管理页只认管理令，且默认只允许部署机直连。

## 四、后果与风险

- 正面：可见性由工具面 + 台账两层表达，审计能回答"谁、什么时候、看了哪一篇"。
- 代价：kb 与普通窗口是两套工具面，改动闸门时要分别确认；等级不继承意味着配置量更大。
- 持续跟踪：新增门户入口（下载、打包、预览）时确认都过 `kb.resolve_doc`；签名校验的失效场景要留在测试里。
